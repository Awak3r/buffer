# Буфер · Android → Windows

Выдели текст на телефоне, нажми «Поделиться» → «На компьютер». Когда появится «Готово к вставке на ПК», нажми Ctrl+V в любом текстовом поле Windows. Первая версия передаёт текст до 64 КиБ в одну сторону. Телефон обращается к серверу только при отправке. Компьютер держит исходящее WebSocket-соединение. Устройства могут быть в разных сетях.

Готовые APK, EXE и Linux-бинарники входят в архив `buffer-mvp.zip` на странице [Releases](https://github.com/Awak3r/buffer/releases). Распакуй архив перед установкой.

## 1. Запустить ретранслятор на Linux VPS

Нужны домен или поддомен с DNS-записью на VPS, работающий Caddy и доступные извне порты 80 и 443. На ПК и телефоне входящие порты открывать не требуется.

На сервере открой распакованный каталог buffer. Установи исполняемый файл под свою архитектуру (x86_64 — amd64, aarch64 — arm64) и службу.

```bash
uname -m
sudo install -m 755 dist/buffer-relay-linux-amd64 /usr/local/bin/buffer-relay
sudo install -m 644 buffer-relay.service /etc/systemd/system/buffer-relay.service
```

Один раз создай токен. Сохрани значение после знака равенства для первого запуска ПК. Повторный запуск команды генерации меняет токен.

```bash
sudo sh -c 'umask 077; set -C; echo "BUFFER_TOKEN=$(openssl rand -hex 32)" > /etc/buffer-relay.env'
sudo cat /etc/buffer-relay.env
sudo systemctl daemon-reload
sudo systemctl enable --now buffer-relay
```

Добавь блок из Caddyfile в конфигурацию своего Caddy, заменив clip.example.com своим поддоменом. Если Caddy работает в контейнере, адрес 127.0.0.1 внутри него указывает на контейнер. Пример рассчитан на Caddy, запущенный на самом VPS.

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
curl -s -o /dev/null -w '%{http_code}\n' https://clip.example.com/clip
```

Ответ 401 на запрос без токена означает, что HTTPS дошёл до ретранслятора. Сам ретранслятор слушает только 127.0.0.1:8787.

## 2. Привязать Android к Windows

1. Установи dist/buffer-android.apk на телефон с Android 8 или новее. Это тестовая сборка, подписанная отдельным ключом.
2. На Windows 11 открой PowerShell в папке dist и выполни `.\buffer.exe -pair`. При первом запуске введи HTTPS-адрес без пути и значение BUFFER_TOKEN. Текст отображается в терминале. Используй своё устройство для привязки.
3. Разверни терминал, чтобы QR помещался целиком. Используй тёмный фон со светлым текстом. В Android-приложении «На компьютер» нажми «Сканировать QR с компьютера». Доступ к камере нужен на этом шаге.
4. После сообщения «Компьютер привязан» нажми Enter в терминале. Дождись “Connected”. Пока принимаешь текст, оставь процесс открытым. В следующий раз запускай `.\buffer.exe` без параметров.
5. Отключи Wi-Fi на телефоне, выдели текст в приложении с функцией «Поделиться», выбери «На компьютер». Получив подтверждение, вставь текст в Блокнот. Закрой процесс на Windows и повтори отправку для проверки статуса «Компьютер офлайн».

Для повторного показа QR запусти клиент с -pair. Храни QR приватно. Клиент хранит параметры в %APPDATA%\Buffer\pair.bin под защитой Windows DPAPI, телефон — в файле, зашифрованном ключом Android Keystore. Для смены пары останови клиент, смени случайный токен в /etc/buffer-relay.env, перезапусти службу, удали pair.bin и пройди привязку заново.

## Что происходит при доставке

Телефон шифрует UTF-8 текст с AES-256-GCM и посылает по HTTPS случайный 12-байтовый nonce и шифротекст с тегом. Сервер проверяет отдельный bearer-токен, передаёт пакет активному ПК и ждёт подтверждения конкретного сообщения. Windows проверяет тег, записывает текст в CF_UNICODETEXT и только после записи подтверждает доставку. В журнал приложения содержимое буфера не выводится.

Один экземпляр сервера обслуживает одну пару. Если запустить второй Windows-клиент с тем же токеном, он займёт место первого. Если ПК отключён, текст не ставится в очередь. При разрыве связи после отправки проверь буфер перед повтором: подтверждение могло потеряться после успешной записи.

## Исходники и сборка

* cmd/relay — Go-ретранслятор и интеграционные тесты.
* cmd/desktop — Windows-клиент на Go, QR и Win32 Clipboard API.
* internal/delivery — получение, расшифровка и подтверждение пакета.
* android — Android-приложение на Java с локальным QR-сканером ZXing. Системный интерфейс, без фоновой службы.

На Linux или WSL с Go 1.24.5 и новее:

```bash
go test -race ./...
GOOS=windows GOARCH=amd64 go build -o dist/buffer.exe ./cmd/desktop
CGO_ENABLED=0 go build -o dist/buffer-relay ./cmd/relay
```

Для самостоятельной сборки APK открой каталог android в Android Studio либо используй Gradle 8.9, JDK 17 и Android SDK 35:

```bash
cd android
gradle :app:assembleDebug
```

Локальная debug-сборка будет подписана твоим debug-ключом. Чтобы перейти с комплектного APK на сборку с другим ключом, удали старое приложение и привяжи устройство заново.
