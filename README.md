# Буфер · Android ↔ Windows

Скопируй текст или ссылку в любом приложении. На Android открой шторку быстрых настроек и нажми **«Отправить на ПК»** или **«Забрать с ПК»**. На Windows «Буфер» работает в области уведомлений рядом с часами, без открытой консоли. Устройства могут находиться в разных сетях. Лимит — 64 КиБ UTF-8; изображения, файлы и оформление текста не передаются.

## Скачать

В [GitHub Releases](https://github.com/Awak3r/buffer/releases) начиная с v0.3.0 ищи отдельные файлы `buffer-android.apk` и `buffer.exe` в разделе **Assets**. В архиве `buffer-vX.Y.Z.zip` также есть ретранслятор для Linux amd64 и arm64 и инструкция. В релизе v0.2.0 APK доступен только внутри архива и не содержит плиток.

## Быстрый доступ на Android

- На Android 13 и новее открой «На компьютер» → **«Добавить плитку»** и добавь каждое направление отдельно. На любой поддерживаемой версии можно раскрыть шторку, нажать кнопку редактирования и перетащить плитки в активную область. Поставь их ближе к началу, чтобы видеть при первом свайпе.
- После нажатия плитки ненадолго открывается маленькое окно: Android не даёт прочитать буфер из фоновой службы. При успехе окно закроется; при ошибке останется пояснение. На заблокированном телефоне сначала потребуется разблокировка.
- Кнопки в приложении и отправка через системное меню «Поделиться» остались доступны. Буфер не отслеживается в фоне.

## Обновление

1. Если на VPS ещё v0.1.0, обнови бинарник службы под свою архитектуру и перезапусти `buffer-relay`, сохранив `BUFFER_TOKEN`. Если прокси ограничивает маршруты, добавь `POST /pull` к существующим `/clip` и `/desktop`. Для клиентов v0.3.x достаточно ретранслятора v0.2.0.
2. Закрой старый процесс на ПК и замени `buffer.exe`. Существующий `pair.bin` подходит.
3. Установи новый APK поверх старого. Если Android отклонит обновление из-за другой подписи, удали старое приложение, установи новый APK и повтори привязку через **Pair phone…** в трее Windows.

ПК читает буфер по запросу от привязанного телефона. Телефон проверяет ответ и записывает текст в свой буфер. На сервере нет истории или очереди. При переходе между версиями прежняя отправка текста с Android на Windows остаётся доступной.

## 1. Запустить ретранслятор на Linux VPS

Нужны домен или поддомен с DNS-записью на VPS, работающий Caddy и доступные извне порты 80 и 443. На ПК и телефоне входящие порты открывать не требуется.

На сервере открой распакованный каталог buffer. Установи исполняемый файл под свою архитектуру (x86_64 — amd64, aarch64 — arm64) и службу.

```bash
uname -m
sudo install -m 755 dist/buffer-relay-linux-amd64 /usr/local/bin/buffer-relay
sudo install -m 644 buffer-relay.service /etc/systemd/system/buffer-relay.service
```

Один раз создай токен. Сохрани значение после знака равенства для первого запуска ПК. Повторный запуск команды генерации меняет токен.

```bash
sudo sh -c 'umask 077; set -C; echo "BUFFER_TOKEN=$(openssl rand -hex 32)" > /etc/buffer-relay.env'
sudo cat /etc/buffer-relay.env
sudo systemctl daemon-reload
sudo systemctl enable --now buffer-relay
```

Добавь блок из Caddyfile в конфигурацию своего Caddy, заменив clip.example.com своим поддоменом. Если Caddy работает в контейнере, адрес 127.0.0.1 внутри него указывает на контейнер. Пример рассчитан на Caddy, запущенный на самом VPS.

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
curl -s -o /dev/null -w '%{http_code}\n' https://clip.example.com/clip
```

Ответ 401 на запрос без токена означает, что HTTPS дошёл до ретранслятора. Сам ретранслятор слушает только 127.0.0.1:8787.

## 2. Привязать Android к Windows

1. Установи `buffer-android.apk` из GitHub Releases (или из папки `dist` внутри архива) на телефон с Android 8 или новее.
2. На Windows 11 запусти `dist/buffer.exe` двойным щелчком. При первой настройке введи в открывшемся окне HTTPS-адрес без пути и `BUFFER_TOKEN` (ввод скрыт), затем нажми **Show QR**. Если клиент уже работает, нажми правой кнопкой на значок Buffer в трее и выбери **Pair phone…**. Значок может быть под стрелкой скрытых значков.
3. В Android-приложении «На компьютер» нажми **«Сканировать QR с компьютера»**. Разреши доступ к камере и отсканируй код из окна Windows.
4. После сообщения «Компьютер привязан» закрой окно QR на ПК. Проверь статус **Connected** в меню значка Buffer. Для остановки клиента выбери **Exit** в его меню.
5. Отключи Wi-Fi на телефоне. Скопируй текст в приложении без меню «Поделиться», нажми плитку **«Отправить на ПК»** и вставь текст в Блокнот. Затем скопируй другой текст на ПК, нажми **«Забрать с ПК»** и вставь его на телефоне. Для проверки ошибки выбери **Exit** на ПК и повтори отправку: телефон должен показать «Компьютер офлайн».

**Pair phone…** можно открыть в любой момент, не останавливая обмен. На главном экране Android отображается имя компьютера из QR, а не его IP или адрес VPS. Если старая привязка работает, но показывает **«ПК · без имени»**, просто отсканируй новый QR — сбрасывать пару не нужно.

Храни QR приватно. Клиент хранит параметры в `%APPDATA%\Buffer\pair.bin` под защитой Windows DPAPI, телефон — в файле, зашифрованном ключом Android Keystore. Для смены пары останови клиент, смени случайный токен в `/etc/buffer-relay.env`, перезапусти службу, удали `pair.bin` и пройди привязку заново.

## Что происходит при доставке

Телефон шифрует UTF-8 текст с AES-256-GCM и посылает по HTTPS случайный 12-байтовый nonce и шифротекст с тегом. Сервер проверяет отдельный bearer-токен, передаёт пакет активному ПК и ждёт подтверждения конкретного сообщения. Windows проверяет тег, записывает текст в CF_UNICODETEXT и только после записи подтверждает доставку. В журнал приложения содержимое буфера не выводится.

Один экземпляр сервера обслуживает одну пару. Windows-клиент не запускает второй процесс с тем же локальным файлом пары. Если подключить клиент с тем же токеном с другого компьютера, он займёт место первого. Если ПК отключён, текст не ставится в очередь. При разрыве связи после отправки проверь буфер перед повтором: подтверждение могло потеряться после успешной записи.

## Исходники и сборка

* cmd/relay — Go-ретранслятор и интеграционные тесты.
* cmd/desktop — Windows-клиент на Go, значок в трее, QR и Win32 Clipboard API.
* internal/delivery — получение, расшифровка и подтверждение пакета.
* android — Android-приложение на Java с локальным QR-сканером ZXing. Системный интерфейс, без фоновой службы.

На Linux или WSL с Go 1.24.5 и новее:

```bash
go test -race ./...
GOOS=windows GOARCH=amd64 go build -ldflags=-H=windowsgui -o dist/buffer.exe ./cmd/desktop
CGO_ENABLED=0 go build -o dist/buffer-relay ./cmd/relay
```

Для самостоятельной сборки APK открой каталог android в Android Studio либо используй Gradle 8.9, JDK 17 и Android SDK 35:

```bash
cd android
gradle :app:assembleDebug
```

Локальная debug-сборка будет подписана твоим debug-ключом. Чтобы перейти с комплектного APK на сборку с другим ключом, удали старое приложение и привяжи устройство заново.

## CI/CD и публикация релиза

- [CI](.github/workflows/ci.yml) запускается на pull request и при пуше в `main`: проверяет обмен в обе стороны с `-race`, запускает тесты клиента на Windows, собирает EXE и Linux-бинарники для обеих архитектур, проверяет Android через lint и собирает APK без подписи. Секреты этим проверкам не нужны.
- [Release](.github/workflows/release.yml) запускается при пуше тега `vX.Y.Z`. Он проверяет, что тег указывает на коммит в истории `main` и совпадает с `versionName`, повторяет CI для этого коммита, подписывает APK, проверяет подпись и выкладывает файлы в GitHub Releases. VPS автоматически не обновляется.

### Один раз: настроить подпись APK

1. Используй тот же keystore, которым подписана установленная версия, если он сохранился и нужно сохранить возможность обновления. Если его нет, создай новый постоянный ключ и сохрани резервную копию в защищённом месте. Для первого обновления с другим ключом понадобится переустановка приложения.
   ```bash
   keytool -genkeypair -keystore buffer-release.p12 -storetype PKCS12 -alias buffer -keyalg RSA -keysize 3072 -validity 10000
   ```
2. На GitHub в **Settings → Environments** создай окружение `release`. В **Deployment branches and tags** можно разрешить только теги `v*` (выбери тип правила **Tag**).
3. В **Environment secrets** этого окружения добавь `ANDROID_KEYSTORE_BASE64` (содержимое keystore в Base64 одной строкой), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (`buffer` для команды выше). `ANDROID_KEY_PASSWORD` нужен только если пароль ключа отличается от пароля keystore. Если используешь GitHub CLI, Base64 можно передать без вывода в терминал: `base64 -w0 buffer-release.p12 | gh secret set ANDROID_KEYSTORE_BASE64 --env release`. Не добавляй keystore или его Base64 в репозиторий. `BUFFER_TOKEN` для сборки не нужен.

### Выпустить новую версию

1. Увеличь `versionCode`, укажи новый `versionName` в `android/app/build.gradle` и отправь изменения в `main`.
2. Когда CI на `main` пройдёт, поставь тег на проверенный коммит и отправь тег. Для примера, если `HEAD` указывает на проверенный коммит версии `0.3.1`:
   ```bash
   git tag v0.3.1
   git push origin v0.3.1
   ```
3. Дождись успешного запуска **Release** во вкладке **Actions** и проверь файлы в **Releases → Assets**.
